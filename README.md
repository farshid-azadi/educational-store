# فروشگاه کُدورا

وب‌سایت استاتیک فارسی و راست‌چین برای معرفی و فروش محصولات آموزشی. هیچ npm، Node، بک‌اند، کتابخانه یا CDN اجباری ندارد.

## پیش از انتشار: تنظیم `config.js`

فایل `config.js` را باز کنید و این مقادیر نمونه را با اطلاعات واقعی جایگزین کنید:

- `cardNumber` و `cardOwner`: شماره و نام صاحب کارت دریافت‌کنندهٔ وجه.
- `telegramUsername`: نام کاربری تلگرام دریافت‌کنندهٔ فیش، بدون `@` (مثلاً `myacademy`). دکمهٔ ارسال تا وارد کردن نام کاربری معتبر فعال نمی‌شود.
- `supportTelegramUsername`: نام کاربری پشتیبانی، بدون `@`.
- `domain`: نشانی نهایی سایت با اسلش پایانی؛ برای مخزن نمونه، مانند `https://YOUR-NAME.github.io/educational-store/`.
- `brandName` و `products`: نام برند (کُدورا) و اطلاعات محصول‌ها، قیمت، توضیح و ویژگی‌ها فقط در همین فایل تعریف شده‌اند.

نام کاربری تلگرام باید ۵ تا ۳۲ نویسه و شامل حروف لاتین، رقم یا زیرخط باشد. پیش از انتشار، placeholderهای حساب و دامنه را حتماً عوض کنید.

## اجرای محلی

ساده‌ترین روش: `index.html` را با مرورگر باز کنید. برای شبیه‌سازی سرور استاتیک می‌توانید از ریشهٔ پروژه اجرا کنید:

```bash
python -m http.server 8000
```

سپس `http://localhost:8000` را باز کنید. سرویس محلی صرفاً برای پیش‌نمایش است و بخشی از پروژه یا انتشار نیست.

## انتشار در GitHub Pages

1. در GitHub یک repository با نام `educational-store` بسازید و محتوای این پوشه (از جمله پوشهٔ مخفی `.github` و فایل `.nojekyll`) را در ریشهٔ مخزن قرار دهید.
2. در `config.js` مقدار `domain` را با آدرس واقعی GitHub Pages خود تنظیم و تغییرات را روی شاخهٔ `main` push کنید.
3. در repository به **Settings > Pages > Build and deployment > Source** بروید و **GitHub Actions** را انتخاب کنید.
4. گردش‌کار `Deploy static site to GitHub Pages` با هر push به `main` اجرا می‌شود؛ برای اجرای دستی از تب **Actions**، workflow را انتخاب و **Run workflow** را بزنید.
5. پس از پایان موفق workflow، نشانی سایت در بخش Pages و در خروجی job انتشار نمایش داده می‌شود. اولین انتشار ممکن است چند دقیقه زمان ببرد.

## دامنهٔ اختصاصی (اختیاری)

1. نام دامنه را در **Settings > Pages > Custom domain** وارد کنید و فایل `CNAME` را در ریشهٔ مخزن بسازید؛ محتوای آن فقط نام دامنه است، مانند `learn.example.com` (بدون پروتکل و مسیر). این فایل را خود GitHub نیز ممکن است هنگام ذخیرهٔ دامنه بسازد؛ در ریشه نگه دارید.
2. در پنل DNS شرکت ثبت‌کننده، برای زیردامنه یک رکورد `CNAME` به `<username>.github.io` بسازید. برای دامنهٔ ریشه، رکوردهای `A`/`AAAA` را مطابق نشانی‌های IP جاری مستندات GitHub Pages تنظیم کنید؛ IPها را از مستندات روز GitHub بررسی کنید و از DNS provider خود بپرسید.
3. مقدار `domain` در `config.js`، تگ canonical و نشانی `https://` دامنهٔ نهایی را هماهنگ کنید. پس از انتشار و فعال شدن DNS، گزینهٔ **Enforce HTTPS** را در Pages فعال کنید. انتشار DNS و صدور گواهی ممکن است زمان ببرد.

## پرداخت و حریم خصوصی

GitHub Pages فقط میزبانی استاتیک ارائه می‌دهد: این پروژه بک‌اند، درگاه پرداخت، پردازش پرداخت یا امکان آپلود امن فایل ندارد. در نسخهٔ فعلی، خریدار کارت‌به‌کارت می‌کند و فیش را خودش در تلگرام به پشتیبانی می‌فرستد. سایت پس از کلیک، پیام پیشنهادی را در صفحه می‌سازد/کپی می‌کند و گفت‌وگوی تلگرام را باز می‌کند؛ کاربر باید تصویر فیش را دستی ضمیمه کند. تلگرام ارسال خودکار پیام یا تصویر از این صفحه را مجاز نمی‌کند.

بررسی فیش و تأیید پرداخت کاملاً دستی است؛ کلیک یا ارسال پیام به معنای تأیید پرداخت یا فعال‌شدن خودکار دسترسی نیست. فرم فقط نام و شماره موبایل را می‌گیرد و آن‌ها را در `localStorage` همان مرورگر برای آماده‌سازی پیام نگه می‌دارد. این اطلاعات بین دستگاه‌ها منتقل نمی‌شود؛ اطلاعات کارت خریدار، رمز، CVV2 یا رمز یک‌بارمصرف را در سایت وارد نکنید. پاک‌کردن دادهٔ مرورگر، این اطلاعات محلی را حذف می‌کند.

## فایل‌ها

- `index.html`: محتوای صفحه، metadata و اجزای رابط.
- `styles.css`: تم واکنش‌گرا و پشتیبانی از کاهش حرکت.
- `app.js`: رندر محصولات، سبد پرداخت نمایشی، کپی پیام، منو و FAQ.
- `config.js`: برند، محصولات و تنظیمات فروش.
- `.github/workflows/deploy.yml`: ساخت artifact و انتشار خودکار در Pages.
